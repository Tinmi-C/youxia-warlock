# UI 方案拍板包（H-UI 人工关卡）—— loop-td v2 · 三套设计提案

> **怎么看**：每套方案一个目录（`plan-A/`、`plan-B/`、`plan-C/`），各 10 张 1280×720 PNG。
> 先看每套的 `01-panorama-build.png`（备战全景）与 `02-panorama-combat.png`（战斗全景）建立整体印象，
> 再翻 `03`~`10` 各面板特写（每张只显示该面板，其余隐藏）。
> 生成方式：真机引擎内截图（`cargo run -p loop-td -- --ui-mock <A|B|C>`，帧脚本驱动，含真实战斗管线）。
> 设计依据：`engine/warbase/docs/ui-design-brief.md`（题材推导、四负面约束→设计规则、token 表、组件规格）。

## 拍板问题（只选一个）

**三套里选哪一套进入 LT2-UI 落地？**（可附带意见：如「A 的布局 + B 的配色」——布局与色彩已全部
token 化，组合成本为零。）

---

## 方案 A · 铁金条约（Iron & Gold）—— 经典魔兽暗金属控制台

- **定位**：WC3 正统复刻。底部通栏控制台（英雄面板｜命令卡+技能｜物品栏一体），左上资源铭牌，
  右上小地图；暗铁底 + 金色点缀，2px 粗边框，近方角，字号最大。
- **一句话**：重、稳、正——塔防本体运营向，WC3 老兵零学习成本。
- **布局图**（`plan-A/01`）：
  ```
  ┌────────┬──────────────────────┬────────┐
  │ 资源铭牌 │      波次横幅(W8)      │ 小地图  │
  │ 金/木/人口│                      │ 环+点阵 │
  ├────────┴──────────────────────┴────────┤
  │              战场（环形跑道）              │
  │                          羁绊提示(右侧) →│
  ├────────┬──────────────────────┬────────┤
  │ 英雄面板 │ 命令卡(技能行+2×4格)   │ 物品栏  │
  └────────┴──────────────────────┴────────┘
  ```
- **优势**：信息容量最大；命令卡/物品栏/英雄像成组在 console，操作视线集中；最贴「魔兽感」。
- **劣势**：UI 面积占比最高（~22%），遮战场下缘；厚重风格在小窗口可能显挤。
- **适用**：主打塔防运营深度、长时间对局、WC3 情怀用户。

## 方案 B · 悬环浮层（Halo Deck）—— 现代极简浮岛

- **定位**：四角/四边浮岛：左上英雄卡、顶中资源胶囊、右上小地图、底中命令岛（脱边悬浮）、
  左中羁绊提示；冷灰蓝半透玻璃 + 单一青色强调，12px 圆角、1px 细边、字阶紧凑。
- **一句话**：轻、透、利——观感现代，截屏传播友好。
- **布局图**（`plan-B/01`）：
  ```
  ┌────────┐ ┌────资源胶囊────┐ ┌────────┐
  │ 英雄卡  │ │ 金/木/人口+存量 │ │ 小地图  │
  └────────┘ └──波次(W8 IN 11s)─┘ └────────┘
  │羁绊提示│      战场（环形跑道）
  └────────┘        ┌──────────┐
                   │ 命令岛+技能 │ 物品栏
                   └──────────┘
  ```
- **优势**：视觉最轻；浮岛可按需显隐（后期只留命令岛）；现代玩家审美安全牌。
- **劣势**：半透明底在浅色地面上对比度需要盯（本方案已用 0.80 alpha 保底）；信息容量次于 A。
- **适用**：想要「不像上个时代的游戏」的观感；直播/截屏场景。

## 方案 C · 低语界面（Whisper UI）—— 沉浸低占比

- **定位**：UI 退到边缘发丝簇：右上微资源簇、顶中波次细线、顶中英雄窄条（一条 HP/MP/XP 微条内联）、
  底中单排 8 槽命令行、右侧微型环形小地图；暖暗褐 + 琥珀微光，无边框、低透明度、最小字阶。
- **一句话**：战场即界面——大屏沉浸、观赏优先。
- **布局图**（`plan-C/01`）：
  ```
                      ┌─波次细线─┐  ┌资源簇┐
                      └英雄窄条──┘  └微地图┐
                战场（环形跑道，几乎全裸）
                         ┌羁绊(toast)→│
            ┌──────单排8槽命令行──────┐物品微排
            └────────────────────────┘
  ```
- **优势**：战场可见面积最大（UI ~8%）；后期观赏/录屏最漂亮；性能负担最小。
- **劣势**：信息最少——深运营信息（三围/羁绊明细/物品 tooltip）必须收进二级交互；
  小字阶对低分屏不友好（R4 靠对比度补偿，弱于 A/B）。
- **适用**：主打后期观赏、大屏、直播沉浸感；或作为「简洁模式」与 A/B 组合。

## 三套共同点（拍板不随方案漂移的部分）

- 命令卡结构同构：QWER-ASDF 网格、热键角标、禁用灰、hover tooltip——操作肌肉记忆跨方案一致。
- 语义色一致：金=资源、绿=生命、蓝=魔法、红=敌方/危险、黄=警示（brief §5.2 token 表）。
- 全部由 `UiTheme` token 驱动（warbase `ui` 域）：换肤=换资源零代码（测试已断言）。
- 存量条三档：常态黄预警 ≥70%、90% 红线刻度、逼近上限红脉冲（占位）。

## 已知限制（三套共有，落地前需解决）

1. **CJK 字体缺失**：bevy 默认字体无中文字形（现有 HUD 中文在真机上是豆腐块）。方案 mock 全用
   ASCII 标签（WC3 EN 语汇）。LT2-UI 第一件事：引入 CJK 字体（warden 已有 NotoSansSC 可上收共享）。
2. 图标全部为几何占位（圆=金/方=木/菱形近似=胶囊/圆点阵=小地图），美术解冻后按 token 槽位替换。
3. 英雄三围（STR/AGI/INT）为占位数字——真实数值随 HERO 线（Phase 1 并行）接入。
