# UI 设计系统 Brief —— 循环圈塔防 RPG（UI-DSGN，ADR-0018 Phase 1）

> 状态：设计先行稿（2026-10-26），供 H-UI 看图拍板的前置文档。
> 范围：loop-td v2 的全量界面（主 HUD 资源条 / 命令卡 / 物品栏 / 技能栏 / 英雄面板 / 羁绊提示 / 小地图）。
> 美术资产冻结：一切用 bevy 原生（纯色 / 形状 / 文字）。灰盒设计 ≠ 敷衍设计——布局系统、层级、字阶、
> 色彩纪律、组件规格都在本文件数字化，主题 token 全部落在 `UiTheme` 资源（serde 全字段化）。

---

## 1. 题材推导

**游戏是什么**：循环圈塔防 RPG（魔兽风）。怪物绕环形跑道循环刷层，玩家沿圈造塔、养英雄塔（吃经验/天赋/装备），
漏怪不死、活怪存量施压；后期有羁绊（塔组合联动）、神器、挑战波。

**题材关键词 → 设计方向**：

| 题材事实 | 设计推论 |
|---|---|
| 魔兽风（WC3 血统） | 暗色低饱和底 + 金色点缀的「铁与金」色彩语汇；粗边框、实底面板（不是 web 玻璃拟态） |
| 塔防 = 全局俯视 + 长线运营 | **屏幕中央永远是战场**；UI 沿边缘/角落组织，禁止任何中央大面板常驻 |
| RPG = 英雄成长是第二主线 | 英雄面板（等级/经验/血蓝/属性）是一等信息，与资源条同级，不是调试数字 |
| 循环圈 = 一眼要看清圈上压力 | 小地图/存量条是「态势感知」件：存量逼近上限时必须有视觉警示（色彩+脉冲占位） |
| 波次节律（备战→来袭） | 波次状态是全局节拍器：备战/进行中/间歇三态要有明确视觉区分 |
| 快节奏操作（造/卖/升/施法） | 命令卡 QWER-ASDF 8 槽 + 热键角标是操作主入口；hover tooltip 必有 |

**情感目标**：打开游戏第一眼是「我在指挥一场魔兽式战役」，而不是「我在看一个调试程序」。

## 2. 四项负面约束 → 设计规则（逐条转化，每条可验收）

用户对现有 UI（warden 命令卡 + loop-td 灰盒 HUD）四项全否。逐条转成硬规则：

| # | 负面约束 | 设计规则（R-x） | 验收方式 |
|---|---|---|---|
| 1 | **布局结构**（工程师布局：一行调试文本塞满所有信息） | R1 屏幕分九宫格锚区，面板只进锚区，战场核心区（屏幕中央 50%×50%，完全覆盖环形跑道）常驻面板数 = 0；每面板单一职责，信息项 ≤ 7±2；同类信息成组（console = 命令卡+物品栏一体），禁止「一行文本多职责」 | 看图 + 数字测试：全景截图中央 50%×50% 核心区无 UI 遮挡（ui_mock::tests 落断言） |
| 2 | **视觉风格**（调试感：裸文字浮在场景上、无背景、无层级） | R2 每个信息组必须有实底面板承载（底座-槽位-内容三层结构）；色彩只用 token 表内的色；圆角/边框/间距/字阶四件套统一（同一组件类同一规格）；图标位用几何图形（圆=金、方=木、菱=人口、竖条=存量），禁止纯文字堆 | 看图：无任何「裸文字贴场景」 |
| 3 | **整体游戏感**（不像魔兽、不像游戏） | R3 语义色阶向 WC3 看齐：金=资源、绿=生命、蓝=魔法、红=敌方/危险、黄=警示、白=中性正文；面板底色暗金属/暗石色系（非纯黑非纯灰）；热键角标、血条、物品格等品类符号（RTS 玩家零学习成本）全保留 | 看图：风格问卷「像不像魔兽风塔防」 |
| 4 | **信息可读性**（18px 单行 HUD 中文挤成一行） | R4 四级字阶固定映射（数值大/标签中/说明小/角标微，见 §5）；关键数值（金/存量/波次/英雄等级）用「数值级」字号 + 图标位引导；深底浅字对比度 ≥ 4.5:1；数字右对齐、带图标位锚定视线；存量条有刻度与上限红线 | 看图 + 规格表对照（每面板字号可查表） |

> 已知硬限制：bevy 默认字体无 CJK 字形（当前 loop-td HUD 的中文在真机上是豆腐块——这本身就是可读性被否的原因之一）。
> 方案 mock 全部用 ASCII 标签（WC3 EN 语汇：GOLD/WAVE/LV，品类惯例反而更地道）；**LT2-UI 落地前需引入一款 CJK 字体资产**
> （warden 已有 NotoSansSC 可上收共享，属资产解冻后的第一件事）。本限制写进三套方案的共同风险栏。

## 3. 布局系统（网格与分区）

- **画布**：1280×720（当前窗口规格）为基准设计；所有锚区用百分比+像素混合定位，UI 缩放跟窗口。
- **九宫格锚区**：
  - `TL`（左上）：资源/英雄 · `TC`（上中）：波次节拍 · `TR`（右上）：小地图
  - `BL`（左下）：英雄像/属性 · `BC`（下中）：命令卡+技能栏 · `BR`（右下）：物品栏
  - 中央 50%×50% = 战场核心禁区，完全覆盖环形跑道（R1，有数字断言）。
- **对齐纪律**：同一锚区内的面板共享基线与间隙（gap 4/8/12 三档，见 token）；角标（badge）永远在槽位右上角 2px 内边距。
- **三套方案的布局差异是结构级的**（不是换色）：面板的锚位、成组方式、占比、可见性策略不同，见 §7。

## 4. 信息层级原则

1. **一眼三级**：态势（存量条/波次状态）> 资源（金/木/人口）> 操作（命令卡）。视觉权重（字号/色彩/面积）依次递减，
   任何面板不得反过来抢戏。
2. **数值优先**：所有计数展示为「图标位 + 数字」，数字用 value 字阶；标签（GOLD/WAVE）用 label 字阶弱化。
3. **状态即颜色**：血=绿→红渐变阈值、蓝=魔法、黄=警示（存量 > 70% 上限时存量条转黄、> 90% 转红并脉冲）。
4. **密度分区**：常驻面板 ≤ 7 项信息；深信息（英雄三围、羁绊明细、物品 tooltip）收进 hover/选中态，不常驻。
5. **进度可视化**：血/蓝/经验/冷却全部用条形（fill 百分比），冷却另加遮罩+剩余秒数。

## 6. 组件规格（灰盒件，全部纯色/形状/文字）

| 组件 | 规格 | 三层结构 |
|---|---|---|
| 面板 Panel | 实底 `panel_bg` + 1-2px 边框 `panel_border` + `radius_panel`；内边距 = `slot_pad`×2 | 底座→槽位→内容 |
| 命令槽 Slot | `slot_w×slot_h`，实底 `panel_raised`，标签居中偏上 + 说明级副行；热键角标右上（`accent` 色）；禁用 = `slot_disabled_bg` + `text_dim` | 底座→槽位→（标签/副行/角标） |
| 资源条 ResourceBar | 图标位（圆=金/方=木/菱=人口）+ value 数字 + label 小字；组内水平排列 gap=panel_gap | — |
| 存量条 StockMeter | 横条 `bar_h`+，fill = 存量/上限百分比；≥70% 转 `warning`，≥90% 转 `health_low`；右端刻度线 | — |
| 血/蓝/经验条 Bar | 底槽（`panel_bg` 抬亮 10%）+ fill 百分比 + 数值小字叠加 | — |
| 技能槽 SkillSlot | 方槽（≈slot 0.8 倍），冷却 = 顶部向下的 `cooldown` 遮罩（高度=剩余%）+ 剩余秒（caption）；角标热键 | — |
| 物品格 ItemSlot | 方格 3×2 或横排，占位用几何形（菱/圆/方组合）+ 数量角标右下 | — |
| 英雄面板 HeroPanel | 头像位（大方框+等级角标）+ 名/等级 + 三条 Bar（血/蓝/经验）+ 三围占位（STR/AGI/INT caption） | — |
| 羁绊提示 BondChip | 小胶囊（`radius_pill`）+ 菱形图标位 + 「组合名 + 效果一行」caption；未激活 50% 透明度 | — |
| 小地图 Minimap | 方形面板，环形跑道 = 圆角矩形描边；塔=绿点、怪=红点、视野框=`accent` 描边；顶角波次小徽 | — |
| 波次节拍 WaveBanner | TC 位窄条：`WAVE 7 · INCOMING`（warning 色）或 `NEXT IN 12s`（中性），备战倒计时数字 value 级 | — |

## 7. 三套方案定位（真实设计差异，出图对照）

| | 方案 A · 铁金条约（经典魔兽暗金属） | 方案 B · 悬环浮层（现代极简） | 方案 C · 低语界面（沉浸低占） |
|---|---|---|---|
| 一句话 | WC3 暗金属控制台的正统复刻 | 悬浮半透明面板的现代 RTS | UI 退到边缘、战场即界面 |
| 布局 | 底部通栏 console（像+命令卡+物品一体），资源 TL 排、小地图 TR | 四角浮岛：命令卡 BC 脱边悬浮、英雄 TL 卡、资源 TC 胶囊、小地图 BR 圆角 | 极简角标簇：资源 TR 微簇、命令卡 BC 单排 8 槽小格、英雄只留 TC 窄条 |
| 面积占比 | ~22%（重、稳、正） | ~15%（轻、透、利） | ~8%（近无 UI，沉浸优先） |
| 色彩 | 暗铁底 + 金色系强调（gold accent 化） | 冷灰蓝底 + 单一青强调 | 暖暗褐底 + 琥珀微光 |
| 圆角/边框 | 方角 2px、2px 粗边框（结构件感） | 12px 圆角、1px 细边、底 alpha 0.78 | 4px、无边框仅底色 alpha 0.55 |
| 字阶 | label 15 / value 22（粗大） | label 12 / value 18（紧凑） | label 11 / value 16（微缩） |
| 适用 | 重操作重运营的塔防本体向；WC3 老兵零学习 | 观感现代、截屏传播友好 | 后期观赏/直播/大屏沉浸 |
| 风险 | 面积大→挡战场下缘；灰盒下「金属感」只能靠色阶暗示 | 半透明在浅色地面上对比度要盯（R4） | 信息最少→运营深度信息要靠 hover 二级菜单补 |
| 负面约束自审 | R1✓（console 全在底缘）R2✓ R3✓✓（最贴魔兽）R4✓ | R1✓ R2✓ R3✓（现代但不背离语义色）R4✓ | R1✓✓ R2✓ R3✓（游戏感靠留白）R4△（字号小，靠对比度补） |

**共同自审**（三套都过）：无裸文字（R2）、语义色一致（R3）、命令卡结构（QWER-ASDF+角标+tooltip）三套同构——
拍板选的是「布局与气质」，操作肌肉记忆不随方案漂移。

## 8. 交付物与验收

1. `UiTheme` 资源（palette/typography/spacing/radius/state_colors 全 serde 字段化）+ 默认主题 = 现行值（零漂移）。
2. 换肤断言测试：mutate `UiTheme` → 面板 `BackgroundColor` 查询变化，渲染代码零改动。
3. `ui-proposals/plan-{A,B,C}/` 各 ≥8 张 PNG（1280×720，引擎内截图）：全景×2 + 各面板特写。
4. 本 brief + 每方案一页说明（`ui-proposals/README.md`）→ **H-UI 看图拍板** → 《UI 设计系统规格》入库（拍板后）。

## 拍板记录（H-UI，2026-10-27）

用户看过三套方案（ui-proposals/ 各 10 张引擎真截图）后拍板：**方案 A · 铁金条约**——经典魔兽暗铁+金控制台布局为 loop-td v2 及后续面板的基准设计。B/C 的可取元素（B 的克制强调色、C 的战场净空比例）作为 A 演进时的备选 token 融入，不整体采用。此决策即 LT2-UI / WARDEN-SKIN 增量的样式权威依据。
