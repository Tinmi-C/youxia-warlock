# ADR-0005: 表现层动画状态机迁移 bevy_animation_graph（数据驱动动画图）

## 背景

- `games/wave-survival/src/plugins/presentation.rs` 已达 1118 行、混杂 7 种职责；
  其中 `sync_walk_playback` 约 240 行是**手写动画状态机**（`HeroClip` 枚举 +
  if/else 分支 + one-shot 窗口计时 + 战斗边沿检测 + 播放速率刷新）。
- 动画规模确定会增长：卡 28（上下半身 mask 分层）已在路线图，死亡/连招等
  状态可期。每加一个状态都要改这个巨型函数，是「改一处崩三处」的温床。
- 用户拍板的工程判断（2026-09-01 讨论）：**对路线图上确定的复杂性，提前搭
  结构是划算的**——伤害管线（commit `5b6ac27`/`941a563`，见主题笔记
  `docs/topics/engine/unified-damage-pipeline.md`）已是先例。动画层适用同一原则。
- 团队规则（根 AGENTS.md）：客观技术能力优先引生态插件，选型先查
  「版本对齐 0.19 + 维护度 + 作者可信」。

## 决策

采用 **bevy_animation_graph v0.11.0** 作为表现层动画状态机：

- 状态 = 图节点，转场 = 条件边，混合/循环/速率 = 图数据；手写 `HeroClip`
  枚举状态机由图解释执行取代。
- **范围只限表现层动画播放决策**。逻辑组件（`WalkCycle`/`Attack`/`Visual`/
  `EquippedWeapon`/`Hp`）与「逻辑/表现分离」边界不变；headless 回归不受影响。
- 迁移纪律：行为保持——既有回归全绿 + 零警告 + clip 切换日志通道逐字兼容；
  走一卡一提交（配套卡 32）。
- **刻意不引入**该生态里更重的未用能力（8 向混合树、root motion、可视化
  编辑器流程）——它们不在路线图上，属「为猜测预付复杂度」，与本决策的
  「为确定路线图预付结构」边界相反。

## 备选方案

| 方案 | 结论 | 理由 |
|------|------|------|
| A 自研维持现状（模块拆分 + 调参表 + 状态机抽纯函数） | 未选 | 风险最低，但状态逻辑仍在代码里，扩状态仍要改控制流，只是变短不变无 |
| B 自研「状态 + 转发表」轻量状态机 | 未选 | 要自维护一个状态机引擎——在引擎层造轮子，违背 ADR-0004 以来「不手写引擎件」的既定方向 |
| C bevy_animation_graph v0.11.0 | **采纳** | 动画专用（直接接管 clip 切换/混合）+ 与锁定版本完全兼容（见下验证） |
| C′ seldom_state v0.16.0 | **淘汰** | ① 版本硬伤：`cargo tree` 实测其依赖树为 bevy 0.18.1 子 crate（bevy_ecs/bevy_app 0.18.1），与锁定 0.19.1 双版本共存、类型不互通；② 定位错配：通用实体行为状态机、不懂动画，用它仍需自写「状态→clip」桥接 |

**选型验证证据（2026-09-01 编译 spike）**：临时工程对 `bevy = "0.19.1"` +
`bevy_animation_graph = "*"`（解析为 0.11.0）执行 `cargo add` → `cargo tree`
→ `cargo check`：依赖树全部为 `bevy_* v0.19.1`（无第二套 bevy），编译干净
通过（dev profile 1m43s，0 错误）。临时验证工程已清理，不入库。

## 影响 / 后果

- **好**：加动画状态 = 图上加节点/边（数据），不再改巨型控制流；卡 28 的
  mask 分层在图模型上是自然扩展而非二次重构；调参（blend/窗口/速率）收进
  图数据，手感拍板权仍在人。
- **代价**：引入第三方运行时依赖（需跟其维护节奏）；团队要学图模型；
  一次性迁移成本（卡 32 承担，回归兜底）。
- **缓解**：headless 测试零改动（逻辑/表现分离边界不动）；clip 切换日志
  格式逐字兼容（观察通道可比）；`seldom_state` 结论有效期——若上游出
  0.19 对齐版再议，当前无计划。
- **跟进**：卡 32 落地后，卡 28 开工时评估 mask 分层在图上的实现路径。
