# ADR-0016: warbase 基底范围扩域——WC3 交互模板九域（修订 ADR-0012 范围条）

## 背景

ADR-0012 把 warbase 定义为「魔兽式战斗 runtime」，但范围实际锚定在 TD 品类（命令卡 + 固定路径 + 建造域）。用户目标升级：**做类魔兽（WC3）的游戏底子，操作交互按魔兽模板**；后续开发统一交子智能体并行推进；美术暂缓（灰盒/bevy 原生）。

缺口分析结论（2026-10-22）：战斗 runtime 半区（攻甲矩阵/伤害管线/技能三分法/金木人口/光环/波次/确定性 harness）对齐扎实；交互半区只兑现了命令卡一根支柱。硬缺口：单位选择/框选/编队、右键智能命令 + A/H/S/P、自由移动与寻路、法力/施法时间、生产训练/科研、物品/商店、视野迷雾、多玩家阵营数据层、录像、鼠标拾取抽象、音效语义通道。其中「寻路」在 ADR-0012 被划在边界外，做自由移动地图时必成基底级刚需。

## 决策

1. **九域进基底**：SEL（拾取/选择/编队/智能命令）、MOV（自由移动/命令状态机/网格 A*/软碰撞/阵型）、SPL（法力/施法时间/引导）、MP（玩家/队伍/外交数据层，见 ADR-0017）、PRD（生产训练/科研/集结点）、INV（物品/背包/掉落/商店）、FOG（双层视野迷雾/小地图数据）、AUD（音效语义消息通道）、RPL（录像/确定性回放）。
2. **修订 ADR-0012 §3**：范围条加入上述九域；「不含寻路网格」改为**含网格 A\***（与 BuildGrid 同网格语义）；仍不含渲染、物理、资产管线、脚本系统、netcode（ADR-0002 边界不变）。
3. **总规格 = `docs/topics/engine/warbase-wc3-alignment-plan.md`**：D1–D10 横切决策（六段调度不加段、prelude 分域、MapBundle 向后兼容、确定性纪律、塔索敌不受玩家迷雾等）+ 27 增量 + Phase 0–4 并行批次 + 子智能体任务包模板。SEAM 接缝增量（共享文件一次钉死）是并行开发的硬前提。
4. **兼容铁律**：warden 161 / loop-td 既有断言零漂移；新 SkillDef 字段全带默认值；MapBundle **可选字段追加不 bump `MAP_FORMAT_VERSION`**（schema 超集兼容，旧图零改动可载；破坏性变更才 bump——细化 ADR-0013 的版本语义，不推翻其「拒载不迁移」精神）。
5. **护栏沿用**：新地图必须改基底核心 = 抽象有洞信号（ADR-0012 §6）；Phase 4 的 RTS 验收图（RL 系）为该护栏的正式检验场。
6. **美术不在此轮**：一切新 UI 灰盒（bevy 原生 node/纯色/文字）；音效只发语义消息不挂资产。

## 备选方案

1. **维持 TD 范围，按地图按需扩**：否——基底是主产品（ADR-0012 立意），选择/移动/寻路是下一张 RPG/军团地图的确定刚需，逐图被动扩会反复触发「抽象有洞」复盘。
2. **渲染/物理/资产一并进基底**：否——ADR-0002 边界（游戏驱动、不做通用引擎）不变；本 ADR 只扩「机制层」。
3. **物品/生产/科研留游戏侧孵化（通道 C）**：部分采纳——INV/PRD 的首批实现仍按基底规格走通道 B（基底先行），但消费验证由 RL 验收图承担；无把握机制允许留缝后上收。

## 影响 / 后果

- 优：交互模板一次对齐 WC3；27 增量可四批并行（子智能体）；确定性基建直接收割录像能力。
- 代价：基底复杂度显著上升（约 7 个新模块）；combat/buff 的敌我判定需先收口（SEAM0c Hostility 缝）再扩多玩家，否则返工。
