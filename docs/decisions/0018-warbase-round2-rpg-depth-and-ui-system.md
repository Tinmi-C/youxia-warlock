# ADR-0018: warbase 第二轮扩域——RPG 纵深全量补齐 + UI 设计系统 + 循环圈纵深 v2

## 背景

第一轮（ADR-0016）交付九域后，RTS 验收图 rts-lab 全链跑通并抓出 12 个抽象洞（5 个已上收，7 个记录待修）。对照 WC3 全模板复盘（2026-10-23）发现三块缺口：①底子级机制缺 15 项（RTS 经济建造/技能效果词汇表/英雄深度/野怪昼夜高地/镜头/存档观战）；②UI 全面不满意（用户对 warden 命令卡与 loop-td 灰盒的布局结构/视觉风格/游戏感/信息可读性四项全否）；③「一基座多玩法」只验证了 TD 与 RTS 两极，RPG 半区未验证。

用户拍板（2026-10-24）：框架质量优先不计成本；基底范围=全量 A 层 15 项；第二张验收图=**loop-td 循环圈纵深 v2**（装备/神器/挑战/挖宝/羁绊/多人）；UI 推倒重设计，AI 设计先行 + 用户看图拍板。

## 决策

1. **第二轮基底范围（全量 A 层）**：采集域上收（Harvest 循环/矿储量/维护费 Upkeep）、RTS 建造域（造建筑/多工人加速/主城等级链 T1-T3）、技能词汇表（Area 目标/眩晕沉默/召唤/攻击前后摇）、英雄域（三围换算/祭坛复活/经验分享）、镜头域（滚屏/跳转/缩放/ping）、地图生态域（野怪营地/昼夜循环）、高地（攻击加成+视线遮挡）、对局存档、观战回放。
2. **UI 设计系统进基底 ui 域**：design tokens 数据驱动主题化（游戏可换肤、结构 API 不变）；设计流程=AI 从题材推导设计 brief → 2-3 套灰盒方案截图 → **人工关卡 H-UI 用户看图拍板** → 沉淀《UI 设计系统规格》。旧 UI 四不满点转为负面约束。**本轮不做贴图**（美术仍冻结），灰盒指 bevy 原生节点的结构与层级设计。
3. **loop-td v2 = 第二张验收图（RPG 半区）**：先采用改造（接鼠标选择链/数字键模态让渡/物品域）再纵深（装备上塔/神器/挑战波/挖宝/羁绊/多人漏怪）。warden 面板仅做 token 级换肤验证换肤成本，完整重设计后置。
4. **洞 #6-12 清账**与 SEAM2 接缝修订（事件资源翻消息/Order 扩展/新域骨架）先行，沿用第一轮「共享文件一次钉死=并行硬前提」制度。
5. 修订 ADR-0016 的范围条：本轮新增域全部纳入「魔兽式战斗 runtime」边界内；脚本/netcode/美术资产仍排除。

## 备选方案

1. 核心优先（A 层部分后置）：否——用户明示框架优先不计成本，半途补域会重复触发抽象有洞。
2. 新立项一张 RPG 图而非 loop-td v2：否——用户疑虑的架构问题经评估不存在（loop-td 是基底第一公民，差距仅为采用债），v2 改造成本低于新图且历史包袱少。
3. UI 等美术解禁一起做：否——四项不满含布局结构与信息可读性等结构性问题，与贴图无关；灰盒阶段即可定布局与层级。

## 影响 / 后果

- 优：WC3 模板 A 层一次补齐；UI 有了可换肤的设计系统底座；「一基座多玩法」三极验证（TD/RTS/RPG）。
- 代价：约 34-38 增量的新一轮开发；基底 ui 域引入主题层（API 兼容、渲染实现需迁移）。
