# ADR-0013: MapBundle 数据文件化——「地图」是自包含数据包（RON），不是代码模块

## 背景

ADR-0012 把基底定为产品、玩法做成「地图」。魔兽生态里地图是自包含数据包（对象数据 + 触发 + 导入资产），换图不换宿主。v1 草案曾按 [[decisions/0008-numeric-data-in-code-not-external|ADR-0008]]（数值暂留代码内）把 MapBundle 留在代码中、「结构按可序列化组织」。用户拍板效果优先后重新评估：bundle 不成文件，「同一二进制加载不同地图」这个基底的核心产品效果就无法做实，也堵死后续轻量工具（查看器/校验器/编辑器）的路。ADR-0008 的原意是「不为数据驱动而数据驱动、防过早外部化」；地图文件化不是过早外部化，而是产品形态本身的要求——适用范围应当收窄。

## 决策

1. **MapBundle 以 RON 数据文件为唯一正式形态**，位于 `games/<game>/maps/<map>.ron`，随 git 走；包含：地图 id/版本、路径拓扑、建造域定义、单位/技能/光环/天赋定义表、波次表、规则参数（漏怪策略/资源初值/建造窗口/胜负）、攻甲系数矩阵、资产引用（场景/贴图路径）、代码挂钩 id（场景构造器、特有效果系统的注册名）。
2. **代码挂钩按 id 注册**：基底维护注册表（`scene_spawners` / `map_effects` / `custom_commands`），游戏插件启动时注册实现；bundle 文件里只写 id。对应魔兽「Object 数据 + Trigger 导入」的分工。
3. **装载层即校验层**：加载时做 schema 校验（必填/枚举/引用存在性：技能 id、资产路径、挂钩 id 悬空即拒载并报可读错误），带版本兼容检查。warden/loop-td 的 bundle 与迷宫冒烟 bundle 同一装载器。
4. **ADR-0008 适用范围收窄**（不取代其精神）：地图内容数值（塔/怪/波次/经济初值/系数表）→ 进 bundle 文件；**基底机制参数与跨地图仍单份的团队约定**（如测试常量）→ 仍在代码内；数据库/远端化仍然不做、不设迁移计划。
5. 工具演进按需：RON 定稿后，查看器/校验器（CI 里跑全 bundle 校验）成本低；编辑器仍后置（重开条件不变）。

## 备选方案

1. **bundle 留代码内（v1 方案）**：省序列化层，但「地图=数据包」停留在口头，工具链无从谈起。否。
2. **JSON/TOML**：RON 是 Rust 生态原生（serde 全兼容、注释友好、rust-analyzer 相邻体验），选 RON。
3. **完整脚本化地图（bundle+逻辑都进文件）**：超出本决策——逻辑侧仍按 ADR-0012 走「薄 Rust 插件 + 挂钩 id」。

## 影响 / 后果

- 优：`loop-td --map maps/maze-smoke.ron` 换文件即换玩法可现场演示；地图可 diff/review/版本化；CI 校验全 bundle；为工具链留正门。
- 代价：先写 serde 类型与装载校验层（一张卡的工作量）；地图改动的评审从「看代码」变「看 RON diff」（团队习惯迁移，AI 辅助生成初稿）。
- 风险：schema 演进兼容——靠 identity 版本 + 装载器明确拒绝策略（不静默迁移），宁可拒载不留隐性行为漂移。
