# ADR-0004：渲染底料开源化——从手写 wgpu 渲染器迁移到 Bevy 全引擎

## 背景

- **教学使命已完成**：M1-M3 手写渲染器（wgpu 五件套 → 渲染管线 → MVP → 纹理/光照/模型加载 → 实例化）全部闭环，学习价值已兑现（对应能力卡 1-9 张）。
- **当前卡壳**：玩法扩展 Step 3「换模型 + 程序动画」，玩家模型 CesiumMan / 怪 BrainStem（Khronos 骨骼蒙皮样例）渲染出来「完全不像人」。
- **代码诊断**（`games/m2-bevy/src/main.rs` 的 `load_gltf_mesh`）：只读静态顶点/uv/法线/索引 + 合并全部 primitive + **只取第一个材质的贴图贴满全身** + 无贴图 fallback 棋盘格；**没有蒙皮、没有多材质、没有骨骼动画**。骨骼模型必然渲染成 T 姿势裸模——这不是 bug，是手写渲染器还没长到这一层。
- **与目标冲突**：团队目标是「跑通整个游戏开发流程 + 减少开发工作量」。手写渲染器每加一个功能（纹理/光照/模型/实例化，下一步蒙皮+动画）都要自己造一遍，且迭代慢（改参 → 编译 → 跑 → 肉眼），很难一次性调对——与「减负」直接相悖。
- **目标确认**（2026-08-25）：波次生存做成**成品**，迁移成本不是约束。

## 决策

**将波次生存游戏从「手写 wgpu 渲染 + bevy_ecs」迁移到 Bevy 全引擎（Bevy App + bevy_ecs + 内置渲染/场景/资产/UI），并做成成品。**

- 手写渲染器 git 存档封存（`m2-bevy` 保留作教学参照，同 ADR-0003 保留 `m2-demo` 的做法）。
- **自研分量 = AI 装配层**，不随底料迁移而丢失：能力卡（11 张）+ 验收句 + 标准总线/验收闭环（愿景层，按 ADR-0002「长出来」继续）。装配层与底料解耦——这正是方向纪要 §3「底料用现成，自研装配层」的正式落子。
- 迁移边界：

| 保留（平移） | 替换（用 Bevy 现成的） |
|---|---|
| 12 个系统（已是 bevy_ecs 写法，逻辑可平移） | 渲染层（手写 wgpu → Bevy render + Scene） |
| 组件 struct、游戏数值 | App / 事件循环 / 输入 |
| 能力卡与验收句 | 资产加载（glTF 场景 + 多材质 + **骨骼动画**开箱即用） |
| Wave/Nova 等玩法逻辑 | UI（bevy_ui，替换手写 22 buffer UI） |
| 日志仪表 + 回归测试思路 | 构建（Bevy 桌面构建） |

## 适用范围（2026-08-25 明确）：Bevy = 团队默认游戏底座

本 ADR 不只针对波次生存——**Bevy 是团队所有未来游戏项目的默认引擎底座**，与 Rust（ADR-0001）、AI 装配层（ADR-0002）并列为基础约定：

- 新游戏一律从 `templates/bevy-game/` 模板起步（Bevy 版本锁定 + 插件化骨架 + 日志仪表 + 回归测试 + 能力卡工作流）。
- 手写渲染/自研引擎路线正式退役；「自研」的含义统一为 **AI 装配层**（能力卡 + 验收闭环 + 观察通道 + 标准总线，愿景层按 ADR-0002 继续长）。
- 开发方式随之固定为 **AI 协作原生**：功能先立能力卡（接口 / 行为 / 验收句）→ AI 按卡实现 → 人按验收句验收 → 回归测试钉死 → 一卡一提交。模板内置该工作流（AGENTS.md + 能力卡文档 + 测试骨架）。
- 例外：非游戏的小工具（CLI / 脚本）不用 Bevy，避免杀鸡用牛刀。

## 备选方案

| 方案 | 评价 | 结论 |
|---|---|---|
| A. 维持手写渲染继续扩展 | 蒙皮/多材质/骨骼动画每个都是深水区，与减负目标直接冲突；CesiumMan/BrainStem 已证明瓶颈 | ❌ 放弃 |
| B. 迁移 Bevy 全引擎（本决策） | 模型/动画/材质问题整类消失；全流程现成；与 ADR-0003 的 bevy_ecs 一脉相承 | ✅ 选定 |
| C. 收缩范围：单网格无骨骼模型 + 变换动画混过这步 | 只解决眼前一步，跑不通全流程 | ⚠️ 仅作迁移前的过渡策略（见影响） |
| D. Godot / Unity | 团队栈是 Rust（ADR-0001），AI 装配层愿景基于 Rust ECS；非 Rust 栈割裂 | ❌ 不选 |

## 影响 / 后果

**好处**
- 模型/动画/材质问题**整类消失**：CesiumMan 的骨骼 + Walk/Run/Jump 动画片段开箱即用，多材质正确渲染。
- 迭代速度质变：资产热重载，调参不再每次编译。
- AI 协作减负：Bevy 是超大生态、语料充足，**AI 写 Bevy 代码命中率远高于写手写渲染器（黑盒）**——这才是长期减负的真正来源。
- 全流程（资产导入 / 场景 / UI / 构建）现成，直达「跑通整个游戏开发流程」目标。

**代价**
- 迁移工作量：逻辑可平移，渲染/输入/App/UI 层重写。预估 1-2 周内完成迁移 + 波次功能对齐（不做成品化打磨）。
- Bevy 版本迭代快（breaking changes）：锁版本，跟官方 examples 走。
- 学习成本：Bevy App / Plugin / 组件模式，团队已有 bevy_ecs 基础，曲线可控。

**后续跟进**
1. **先 spike 再全量**（不 big bang）：1-2 天 Bevy 冒烟测试——导入 `hero.glb` + `monster.glb` 播放骨骼动画 + 一个 UI + 一个构建产物。证据到手再迁移。
2. 迁移完成 + 行为一致性验证（沿用日志仪表 + 回归测试，同 ADR-0003 实施方式）后，本 ADR → `accepted`。
3. 过渡策略：spike 期间，如波次游戏主线不想停，可先用单网格无骨骼低模（Quaternius 单网格版）跑 Step 3 的变换动画，作为迁移前的过渡，不作为终态。
4. 成品化阶段：换模型 + Bevy 动画（程序动画可保留为走路颠簸等叠加）+ 打包发布。

## 与既有 ADR 的关系

- ADR-0001：技术栈仍为 Rust，不变。
- ADR-0002：引擎边界「游戏驱动、不做通用引擎」不变；本决策正是其「底料用现成」的延伸——渲染底料也开源化。
- ADR-0003：bevy_ecs 迁移（accepted）是第一步，本决策是第二步——把渲染层也并入 Bevy 全家桶。

## 实施记录（2026-08-25，spike 证据收集）

`games/bevy-spike`（Bevy 0.19.1，全流程冒烟测试），无头 Xvfb + lavapipe 实跑验证，全链路通过：

| 链路 | 结果 | 备注 |
|---|---|---|
| glTF 人形导入（hero.glb / CesiumMan，JPEG 内嵌贴图） | ✅ | 需 bevy `jpeg` 特性（一行 Cargo 开关；默认只带 png/ktx2） |
| 骨骼动画 | ✅ | `AnimationGraph::from_clip` + `AnimationPlayer.play(index).repeat()`；动画时钟推进并循环（约 2s 片段），两帧 diff 证实骨骼在变形 |
| 相机 / 灯光 / 地面 / 阴影 | ✅ | `Camera3d` + `DirectionalLight` + 级联阴影 |
| UI 文本 | ✅ | `bevy_ui` 文本节点（0.19 API：`Text` + `TextFont` + `FontSize::Px`） |
| 构建 | ✅ | 标准 `cargo build` 桌面二进制 |

踩坑记录：Linux 无头运行需 `libxkbcommon-x11-0` 运行时库；Bevy assets 目录默认相对可执行文件解析，直跑二进制需 `CARGO_MANIFEST_DIR`（`cargo run` 自带）。

下一步：按本 ADR 迁移波次生存到 Bevy（12 个系统平移 + 渲染/UI/输入替换），日志仪表 + 回归测试做行为一致性验证后，本 ADR → `accepted`。
