# 循环圈 TD 需求草案 v0.2——基底验证计划的第一张地图（暂名 loop-td）

> **v0.1 → v0.2 重心修订**（2026-10-08，用户拍板方向）：**基底（warbase）是主产品，本游戏是第一张验证地图**。基底架构、落位与演化协议移入 [[topics/engine/warbase-architecture|warbase 架构文档]] 与 [[decisions/0012-warbase-shared-runtime-and-map-architecture|ADR-0012]]；本文只保留「地图」本身的玩法需求与对基底的验收要求。
> **立项后去向**：复制到 `games/<正式名>/docs/requirements.md` 精化为规则唯一依据。
> **待拍板**：§8 决策点。

## §0 一句话定位

**主产品**：魔兽式游戏基底 warbase（一个 crate，服务后续所有玩法）。**本游戏**：循环圈塔防地图——怪物绕圈循环、漏怪不死、活怪存量施压——作为基底的第一个消费方与验收场。一局 20–40 分钟 PvE，v1 单人。

验证关系（基底验收共五条，#0 由 warden 回迁达成、#1–#4 由本游戏达成，细则见架构文档 §七）：

0. warden-on-base：warden 回迁上新底座，160 断言语义不变全绿（通道 A 忠实性）；
1. 薄游戏：本图玩法全部由 bundle 数据 + 薄编排实现，游戏 crate 无基底管线代码；
2. headless：基底 harness 自动打局出锚点读数（任意 bundle）；
3. 多玩法实证：`--map maps/maze-smoke.ron` 同一二进制换地图文件即换玩法；
4. 本文档 §2 的玩法范围全部落在基底能力 + bundle 参数上（凡需要基底新机制的，都是基底卡的验收内容）。

## §1 目标与约束

1. 玩家目标：失败原因可读（哪波漏的、存量怎么滚起来的）；胜利有分数与无尽续玩；build 有取舍（加点顺序 / 天赋抉择 / 功能塔组合）。
2. 团队约束：3 人 + AI；内容走定义表 + AI 美术管线；桌面 3D，Bevy 0.19.1，依赖 `engine/warbase`（path）。
3. v1 不做：联网（规则不锁死多人）、可视化编辑器、剧情、装备/神器、挑战/挖宝小游戏、羁绊（后四项 v1.5/v2）。

## §2 范围：做 / 不做

**v1 做**：单环地图（入口汇入、无出口）、自由建塔（网格占地）、4 基础塔 + 3 功能塔（光环/减速/减甲）+ 3 英雄塔（等级/技能加点/天赋三层养成）、金/木/人口三资源、攻-甲类型克制、30 波 + 2 限时 BOSS 波 + 无尽开关、活怪存量失败线 + 绕圈增益、出怪预告、命令卡 UI、局间 Meta、headless 平衡读数、**最小迷宫 TD 冒烟场景**（基底验收件）。

**v1 不做**：见 §1.3。

## §3 核心玩法循环

```
局外 Meta 解锁（开局加成/新塔入池/天赋页扩展）
   └─> 开局：初始金/木/人口 + 空圈地图
局内循环（波次自动推进，备战与战斗并行——决策点 D1）：
   备战 ├─ 建塔/升级/卖塔（金）
        ├─ 开天赋 / 买人口 / 木换金（木）
        ├─ 看下波预告 → 调 counter（攻甲类型 / 点杀优先级）
        └─ 英雄塔升级加点（4 技能 + 里程碑天赋）
   战斗：怪出怪绕圈 → 塔自动索敌开火 → 漏怪续走（存量 +1，绕圈获增益）
   波次结算：击杀金 + 波次奖 → 下一波倒计时
   └─ 失败：活怪存量 ≥ 上限 | BOSS 超时；胜利：撑过 30 波（无尽可续）
```

与 warden 的体验级差异：无锁建造、波次自动推进——压力来自时间不来自回合；这是循环圈手感的根（调研笔记 §3.2/待验证清单）。

## §4 玩法需求（地图层；归属基底的机制标注 [基底]）

### 4.1 地图与路径

- 单一闭合环（跑道形，塔位密度均匀），入口汇入、无出口；路径拓扑/闭环计数/分支预留 [基底 path]。
- 场内 3–5 个可打爆小金矿（+40 金，教「目标优先级」）——地图特殊规则（薄插件，通道 C）。
- 自由建塔：网格对齐 + 占地判定 + 路径/金矿不可占；建造域（网格 vs 固定位）是 bundle 参数 [基底 bundle]。
- 数据结构支持多环（为水 TD 式多人分区留缝），v1 只做单环。

### 4.2 漏怪与失败规则（bundle rule_set 选型，决策点 D2）

- 漏怪不死，留在环上续走；**活怪存量 ≥ 50（初值，锚点校准）→ 失败**。
- 反拖延软限：每绕满 1 圈永久增益（+5% 移速 / +3% HP，可配置）。
- BOSS 波限时 T 秒，超时判负 [基底 rule + wave 限时]。
- 失败结算屏展示存量曲线（哪波开始滚雪球）——「失败可读」的直接载体。

### 4.3 塔目录（v1 首发；全部为 bundle 定义数据）

| 类别 | 数量 | 举例与职责 |
|------|------|-----------|
| 基础塔 | 4 | 箭塔（穿刺/单体/对空）、炮塔（攻城/AOE/仅对地）、法师塔（魔法/重甲克星）、哨塔（便宜/对空补位） |
| 功能塔 | 3 | 冰霜塔（减速光环）、腐蚀塔（减甲，配点杀）、战鼓塔（增伤光环）——光环走 [基底 buff] |
| 英雄塔 | 3 | 猎手（对单滚雪球）、工程师（经济/金矿向）、风暴使者（AOE 控场） |

- 基础塔 3 级升级；回收返 70%；英雄塔不可回收。
- 英雄塔获取三来源：波次里程碑 / 商店 / 击杀 BOSS。
- 英雄塔养成三层 [基底 skill/经验等级]：等级吃经验 → 技能点加点（1 被动 + 3 主动/自动施法，加点顺序=build）→ 5/10/15/20 级天赋三选一。三属性（力/敏/智）留接口不实装（决策点 D3）。

### 4.4 波次表（30 波 + 无尽）

- 节奏：1–5 教学波 → 每 5 波一个特性波 → 10/20 限时小 BOSS → 30 终 BOSS → 无尽（每 5 波台阶）。
- 特性波示例：快速、重甲（要攻城/魔法）、治疗（要点杀）、光环怪、抗性（换攻击类型）、空中波。特性标记挂 unit_defs [基底]。
- 关键波设计原则：BOSS 波前留「存量回落窗口」，防雪球不可逆。
- 数值占位（进锚点表校准）：波次 HP `40 × 1.18^n`、击杀金 `3 + 0.5n`、波次奖 `20 + 5n`。

### 4.5 经济与攻甲

- 开局 金 120 / 木 5 / 人口 8；木换金 1:25；买人口 2 木/次（+2，价格递增）；天赋 1 木起 [基底 econ 三资源]。
- 攻-甲类型克制表：攻击 5 类 × 护甲 6 类系数矩阵，随 bundle 发布（基底只有机制与系数表结构）。

### 4.6 计分与 Meta

- 计分 = 击杀 × 特性权重 + 存量控制分 + 波次数 + 英雄塔等级分；结算屏 + 本地无尽榜。
- Meta 局间成长：开局加成、新塔入池、天赋页扩展（沿 warden ME1 模式 [基底 Meta 存档接口]）。

## §5 数值锚点（初稿，headless 可测）

| 锚点 | 目标体验 | 可测指标 |
|------|----------|----------|
| A1 首个特性波不团灭新手 | 第 5 波零功能塔，存量峰值 ≤ 10 | harness 自动打局 |
| A2 存量压力可翻盘 | 15 波注入 20 存量，3 波内清回 ≤ 15 | 注入式读数 |
| A3 BOSS 限时是紧的 | 标准 build 打 BOSS 用时 ∈ [0.6T, 0.9T] | 自动打局读数 |

## §7 第一可玩验收信号

1. 模板冷启动 →「建塔 → 怪绕圈 → 漏怪续走 → 存量满 50 失败 / 30 波胜利」全链路无人工干预可复现；
2. 一局 20–40 分钟（锚点校准后）；headless BAL 输出 A1–A3；
3. 回归测试基线 160+（沿 warden 标准），其中基底机制测试与游戏行为测试分层；
4. 迷宫冒烟场景：同基底换 bundle 跑通「两段路径 + 漏怪扣命 + 3 塔」。

## §10 风险（游戏侧；基底风险见架构文档 §八）

1. 玩法内容量（30 波 × 特性 × 10 塔 × 养成）——对策：波次与塔全走 bundle 表，内容扩展=加行；
2. 英雄塔成长 vs 波次强度双指数赛跑——对策：A1–A3 锚点 P1 就接入，不等 P3；
3. 自由建塔 3D 表现与性能（100+ 怪 × 弹道）——对策：P1 早期压测，塔数随人口上限控制；
4. 反拖延参数两难（绕圈增益太弱可拖延磨 BOSS、太强雪球不可逆）——锚点 A2 直接盯。
