# 引擎概念地图（新手入门）

> 引擎相关概念速查。按「什么时候会碰到」排了优先级（⭐=现在，M1/M2/M3=里程碑）。
> 每个概念：一句话定义 + 程序员类比。深挖某概念时在对应主题下写独立笔记。

## A. 运行骨架 —— 游戏怎么「活」起来

| 概念 | 一句话 | 程序员类比 | 何时碰 |
|------|--------|-----------|--------|
| 游戏循环 | 每帧重复：处理输入 → 更新世界 → 画画面 | 每 1/60 秒被闹钟叫醒干一轮活 | ⭐现在（Bevy 内置 App，模板已有） |
| 帧（Frame） | 一帧 = 一次「更新+渲染」完整回合；60fps=每秒 60 回合 | 服务端每 tick 处理一次请求 | ⭐现在 |
| Delta time | 两帧间隔；移动距离 = 速度 × delta | 别用「每帧加固定值」，否则不同刷新率速度不同 | ⭐现在（Bevy `Time`，模板移动测试已钉死） |

## B. 逻辑层 —— 世界怎么运转

| 概念 | 一句话 | 程序员类比 | 何时碰 |
|------|--------|-----------|--------|
| Entity（实体） | 世界里「一个东西」的编号 | 数据库主键 ID | ⭐现在（Bevy 内置 bevy_ecs） |
| Component（组件） | 纯数据（位置/血量/速度） | 表的一行：位置表、血量表 | ⭐现在 |
| System（系统） | 函数：对「拥有某组组件」的实体批量操作 | `UPDATE 位置表 SET ...`（批量） | ⭐现在 |
| World | 装着所有实体+组件的「数据库」，可查询 | 内存数据库 | ⭐现在 |
| 场景图 | 树状层级组织世界（杯子的位置相对桌子） | 文件系统目录树 | M1（Bevy 父子层级） |
| 事件 / 命令 | 事件=已发生的事（广播）；命令=要做的事（可拦截修改） | 事件=消息队列广播；命令=RPC 调用 | M1（Bevy Events / Commands） |
| 物理 / 碰撞 | 算「碰没碰、怎么弹」 | 别自己写牛顿定律，用现成库 | M2（bevy_rapier3d） |

> **ECS 为什么是 AI 最爱的结构**：组件=纯数据（AI 能生成/校验）、系统=独立函数（AI 能单测）、World 可查询（AI 能看到状态验证）。数据+函数+可观测 = AI 的舒适区。

## C. 渲染层 —— 画面怎么来

| 概念 | 一句话 | 程序员类比 | 何时碰 |
|------|--------|-----------|--------|
| 渲染管线（Pipeline） | GPU 把「数据」变「像素」的流水线：顶点→顶点着色器→光栅化→片元着色器→像素 | 生产线：原料→加工→成品 | ⭐了解即可（Bevy 内置，**不亲手写**） |
| Shader（着色器） | 跑在 GPU 上的小程序，决定每个点/像素长什么样（语言 WGSL） | GPU 里的「定制工人」 | ⭐了解即可（需要自定义效果时再碰） |
| 顶点 / 片元 | 顶点=三角形角（位置）；片元=屏幕像素候选 | 顶点=几何点；片元=栅格化后的像素 | ⭐了解即可 |
| 相机 / 矩阵 | 相机=看世界的眼睛；矩阵=坐标换算工具（MVP） | 坐标变换函数 | ⭐M1（Camera3d，MVP 概念了解） |
| 纹理 | 贴在 3D 表面的图（「皮肤」） | 给立方体贴壁纸 | M1（glTF 直接带纹理） |
| 网格 / 模型 | 网格=形状（顶点+三角形）；模型=网格+贴图+材质 | 网格=几何数据；模型=装配好的对象 | M1（bevy_gltf 直接加载） |

## D. 支撑层 —— 资源与工具

| 概念 | 一句话 | 类比 | 何时碰 |
|------|--------|------|--------|
| 资产管线 | 美术文件（.glb/.png/.wav）→ 游戏可用格式的转换加载 | 编译：源文件→目标格式 | M1（Bevy AssetServer 开箱即用） |
| 输入 | 键盘/鼠标/手柄 → 游戏动作（按 W=前进） | 事件→命令翻译层 | ⭐现在（ButtonInput，模板已有） |
| 音频 / UI | 播放声音；血条/背包/菜单 | 子系统 + 2D 渲染叠加 | M1 UI（bevy_ui）/ M3 音频（bevy_audio） |

## E. AI 装配层（总纲特有）—— 真正要「自研」的

| 概念 | 一句话 | 类比 | 何时想 |
|------|--------|------|--------|
| 能力卡 | 每个组件/系统的「说明书」：接口+行为+怎么验收 | API 文档 + 单元测试集 | 现在可开始设计 |
| 标准总线 | AI↔引擎的唯一出入口：注册表+校验+教育性报错 | 操作系统 API | 现在可开始设计 |
| 主体层 / 内容层 | 底座=通用能力（复用）；主体=本游戏独有编排；内容=数据表 | 框架 / 业务代码 / 配置文件 | M2 后 |
| 六原语 | 组件间关系的 6 种表达：接线/数据读/查询/命令/事件/顺序 | 六种「连接模式」 | M2 后 |
| 观察通道 | 运行时一切被只读记录（快照/事件流/trace） | 数据库 binlog / 黑匣子 | 现在可开始设计 |
| 验收闭环 | 「算做完」写成可自动检查的句子，引擎自动跑、出报告 | CI/CD 自动化测试 | 现在可开始设计 |

## 优先级速查（v2 · Bevy 路线）

```
现在        ：游戏循环、帧、delta、ECS、输入、相机（Bevy 内置，模板已有）
M1 垂直切片 ：场景图、事件/命令、glTF 模型、纹理、UI（bevy_ui）
M2 玩法深化 ：物理（bevy_rapier3d）、粒子（bevy_hanabi）、调试面板（bevy_egui）
M3 表现层   ：音频（bevy_audio）、动画（AnimationGraph）、资产管线
总纲专用     ：能力卡、标准总线、观察通道、验收闭环（可与开发并行推进）
```
