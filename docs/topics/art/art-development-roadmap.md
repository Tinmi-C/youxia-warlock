# 美术开发路线图（执行计划）

> 把三份规格（工作流/资产分类/依赖分析）串成时间线。**边界**：本计划覆盖游戏侧全部工作 + 对美术侧（岩库项目）的接口要求；美术内部排期是岩库自己的事。
> 图例：🎮=游戏侧 AI（我）｜🎨=美术侧（岩库）｜👤=用户拍板｜阻塞关系用 ←。

## 总时间线（四批次 + 一个前置）

```
阶段0 工具缝(🎮,1天) ──┐
阶段1 风格定稿(🎨+👤) ──┼──> 批次P0 UI+loop-td模型+音效 ──> 批次P1 warden+VFX ──> 批次P2 legion+语音 ──> 批次P3 环境
                        ┘        (美术🎨+接入🎮并行)          (前置: warden塔阵容🎮立项)
```

## 阶段 0：游戏侧工具缝（🎮，一天级，随时可开工）

UiTheme 贴图字段 + 灰盒/真资产双形态开关（`--art`/bundle 段，headless 测试永不依赖资产）｜art-needs 2D/UI 投影扩展｜需求状态机加态（in_progress/in_review=WIP 预审通道）｜外观相关性过滤（纯数值 def 改动不触发 changed）｜音效需求通道（SfxKind→需求卡）。**完成后美术解禁日即插即用。**

## 阶段 1：风格定稿（🎨→👤，美术线的总开关）

风格圣经 brief（=方案 A 暗铁金气质 + 各游戏题材注脚）→ 美术出 **2-3 张概念图** → 👤拍板定稿 → 圣经入岩库（需求卡统一引用）。同时 👤做第一批需求定稿：loop-td 16 条 draft → locked + 优先级。

## 批次 P0（首产，解锁即可开工——需求源全部就绪）

| 内容 | 量级 | 流程 |
|------|------|------|
| 通用 UI 底材（九宫格）+ 通用/loop-td 图标 | ~10 张 + ~40 枚 | 🎨按 token 色板制作 → 岩库入库 → 🎮art-sync + UiTheme 贴图模式接入 → 自动取证（九宫格畸变/色差）→ 👤H-ART 看图 |
| loop-td 3D 模型（塔 8 型×3 档+怪 5+BOSS+英雄塔） | ~30 件 | 🎨分件规范 GLB → 结构断言+转台像素差 → 🎮def 挂接+动画机（时长对齐前后摇帧窗）→ 👤看图 |
| 通用音效 + BGM | 12 类 + 2 曲 | 🎨ogg → 🎮SfxKind 挂接（通道已验证）→ 👤听感 |

并行性：🎨制作期间 🎮功能开发照常（美术零阻塞是工作流的设计目标）。

## 批次 P1

warden 塔阵容重做模型+敌人文（**前置：🎮 游戏侧立项定 def**——建议尽早上，弦箭动画等它激活）｜VFX 批次（弹道 4-6/命中死亡 4/光环表现 3——fx 消息即接口）｜rts-lab 模型（5 建筑+6 单位，def 已就绪）。

## 批次 P2/P3

P2：legion 模型（雇佣兵 6 种，def 已就绪）｜单位语音变体（跟阵容走）。P3：环境地图美术（地面基调/跑道可视化/迷雾边缘/小地图底图——锦上添花）。

## 验收纪律（每件资产，贯穿全部批次）

字节同步（art-sync）→ 自动取证（结构断言/转台/像素差/九宫格畸变按适用矩阵）→ 🎮挂接 → 👤H-ART 看图（AI 初筛后只看分歧项）→ 再加工回流（手术脚本随资产存档）。

## 风险与对策（源自工作流七缺陷自审）

状态机粗（阶段0修）｜需求噪音（阶段0修）｜回流分叉（手术脚本存档约定）｜风格漂移（基准样张同屏对照验收）｜👤拍板排队（批量看图+AI 初筛）｜美术产能未知（看板加速度字段，岩库侧维护）。
