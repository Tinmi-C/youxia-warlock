# 展示场 v3 实现方案（对应需求文档 v3 · 2 稿，已拍板）

> 定位：整体技术方案——架构、数据模型、系统改动、能力卡拆分、风险与回退。**仍不含代码**；
> 逐卡实现时按能力卡流程（接口/行为/验收句）细化。
> 决策前提：P1 = 操作面板（SM5）∥ 搜索与资产卡（SM6）；P2 = 来源（SM7）+ 升级对比（SM8）；
> P3 = 观察辅助（SM9）；回流提醒暂缓（SM10 预留）；特效零功能但数据模型/面板全留扩展位（N4）。

## 1. 总体架构（不变量）

沿用 ADR-0010 三层，**全部新能力长在引擎 crate**，warden 适配层只多"提供数据"，bin 免费同步受益：

```
游戏适配层（warden / 未来各游戏）     引擎 crate（showroom-viewer）         零接入消费方
  声明"有什么"：catalog              呈现"怎么看"：影棚/面板/搜索/          asset-viewer bin
  （条目 + 组装闭包 + 标签 + 来源）    动画/画廊/相机/（后续）来源与对比      （扫目录自动成 catalog）
```

N4 扩展性的落点：**数据模型加可扩展字段、面板按分区渲染**——将来加"特效"类资产 = 新增一类条目 +
面板多一个分区，骨架不动。

## 2. 数据模型改动（一次到位，P1 立字段、P2 填内容）

```rust
// 条目（引擎 crate）
pub struct ShowroomItem {
    pub name: String,                       // 列表/画廊标签
    pub info_rows: Vec<(String, String)>,   // 资产卡：结构化键值表（替代现在的裸 info 字符串）
    pub tags: Vec<String>,                  // 搜索/过滤元数据：类型、来源、中文名、组合部件名…
    pub origin: Option<Origin>,             // 来源（字段 P1 就立，P2 填充）——N3 联动一
    pub plate/anchor_y/plate_y/gltf/spawn   // 不变
}
pub enum Origin {
    Vault { asset_id: String, version: String }, // 来自岩库（版本号）
    GameLocal { note: Option<String> },          // 游戏自制/组合（回流后改 Vault——SM10 触发点）
}

// 运行时新增资源（引擎 crate）
pub struct SearchQuery { pub text: String }        // 搜索词（空 = 不过滤）
pub struct ShowroomTime { paused, speed }          // 动效时间控制（写虚拟时间，见 §3.2）
pub struct ShowroomTurntable { on: bool }          // 转台
```

info 从字符串改键值表是**破坏性小改**：warden 适配层与 bin 的三处构造同步换，一次提交内完成。

## 3. 功能实现要点

### 3.1 SM6 · 搜索与资产卡（P1，与 SM5 并行）

- **搜索框**在面板顶部（egui text edit）→ `SearchQuery`；命中规则 = 名称/标签**子串**（中英不区分大小写）；
  拼音首字母匹配**后置**（可选 pinyin crate，客观技术引插件，先用精确子串上线）。
- **有效集合**：搜索生效时 = 全分类命中条目平铺；列表与画廊共用同一集合（画廊铺开命中集，跨分类网格）。
- **资产卡**：面板"当前资产"区按 `info_rows` 渲染键值表 + `origin` 行（P2 起有内容）+ tags 行。
- warden 适配层打标签示例：`["塔","融合","神射手","vault:xxx"]`；bin：目录名/文件名派生。
- 验收句草案：注入 100+ 条目，任意目标 ≤3 次输入命中；列表与画廊同步过滤；资产卡逐行显示全部键值。

### 3.2 SM5 · 操作面板 v2（P1，与 SM6 并行）

面板重排为固定分区（上→下）：

```
[搜索框]                      ← SM6
[画廊/聚焦 G] [重置视角 R] [转台 ◐]
[分类树（可折叠）+ 条目列表]
[当前资产卡：键值表 + 来源 + 标签]   ← SM6
[动作区：clip 列表 | ⏸ ▶ | 速度 0.25/0.5/1/2 | 单帧 | 循环/单次]
[帮助 H：快捷键速查]
```

- **现有功能全收编**：切分类/切件/画廊切换/选动作/环绕缩放提示——面板按钮与既有快捷键走**同一游标/资源**，
  天然等效（现有 select/gallery/animate 路径复用，无第二套逻辑）。
- **动效控制走虚拟时间**（暂停/单帧/速度写 `Time<Virtual>`，DB3 已验证的同机制下沉引擎 crate）：
  动画、转台全局一致地慢放/冻结，实现一次全场景生效——**回退项**见 §5（不用逐 clip 的播放器速度 API）。
- 转台 = orbit.yaw 自转；重置视角 = 恢复默认 orbit 参数。
- 验收句草案：不碰键盘仅用面板走通"找资产→进画廊→点选聚焦→选动作→暂停→单帧→0.5x"；0.5x 下动作
  循环时长 ≈ 2×（±10%）；单帧恰好推进一帧姿势。

### 3.3 SM7 · 来源呈现（P2 联动一）

- warden 适配层在 enter 时读资产清单（art-assets.json，ADR-0009 的锁版本清单）建 **路径 → (岩库id, 版本)**
  映射；条目按其模型路径填 `Origin::Vault`，无对应者 `GameLocal`。
- **组合条目多来源**：弩+塔条目 = 两行来源（塔身/床弩各一行）——info_rows 追加，面板直接显示。
- bin：目录无清单概念，条目 origin 留空。
- 验收句草案：六种敌人条目显示岩库 id+版本；弩+塔组合显示两行来源；灰盒/游戏自制条目显示"游戏本地"。

### 3.4 SM8 · 升级对比（P2 联动三）

- **对比模式**：同一资产的新旧两版以游戏组合形态**左右同台**摆放（间距 4，各带版本号铭牌），
  复用画廊的网格铺设与动画接线（两版各自 idle）。
- **两版取材（实现卡二选一拍板）**：
  a. art-sync 已同步的当前版 + 临时拉取新版落 `_art/compare/`（游戏外目录，不入清单）；
  b. 岩库版本目录直读两份。
- 入口：面板"对比新版…"按钮（仅当清单出现待升级提示时可用）。
- 验收句草案：对比模式同台两版、铭牌标版本、退出回聚焦；动画两版独立播放。

### 3.5 SM9 · 观察辅助与打磨（P3）

- 线框（bevy wireframe 特性开关）、骨骼/包围盒 gizmo；画廊 >24 条目分页（← → 翻页）；转台速度可调。

## 4. 能力卡拆分与顺序

| 卡 | 内容 | 期 | 依赖 |
|---|---|---|---|
| SM5 | 操作面板 v2：分区重排 + 现有功能收编 + 虚拟时间控制（暂停/单帧/速度）+ 转台/重置 | P1 ∥ | 无 |
| SM6 | 搜索 + 资产卡：SearchQuery/过滤/键值表/tags + 适配层打标签 | P1 ∥ | 数据模型小改（与 SM5 同一提交先落） |
| SM7 | 来源呈现：清单对账映射 + origin 填充 + 组合多来源 | P2 | SM6（资产卡分区） |
| SM8 | 升级对比模式 | P2 | SM7 |
| SM9 | 观察辅助 + 画廊分页 + 转台打磨 | P3 | SM5 |
| SM10 | 回流提醒（**暂缓预留**：首批自制资产要回流时立卡） | 触发式 | SM7 |

数据模型改动（§2）作为 SM5/SM6 的共同前置，随先落的那张卡一并提交。

## 5. 风险与回退

| 风险 | 判断 | 回退/备选 |
|---|---|---|
| fork 逐 clip 播放器速度/暂停 API 未验证 | 不赌 API | 全局虚拟时间控制（DB3 同机制已验证）；逐 clip 控制留到确有需求再验 |
| 拼音首字母匹配需引 crate | 客观技术引插件成立 | 先精确子串上线，拼音后置为增强 |
| 线框需开 bevy 特性 | 编译面变化 | SM9 才开，先确认 release 面无泄漏 |
| 升级对比两版取材路径 | 依赖 art-sync/岩库现状 | 两选项进 SM8 卡内拍板，都不阻塞 P1/P2 其余部分 |
| 面板功能变多后拥挤 | UI 风险 | 分区可折叠 + 上下文显示（聚焦模式才显动作区）；实测再调 |
