# 技能设计工作流（讨论稿 v1 · 待讨论，未拍板）

> 来源：2026-09-21 负责人提出"技能设计讨论，先调研正常工作流"。
> 调研对象：UE Gameplay Ability System（业界能力系统事实标准）、通用游戏设计迭代流程
> （设计文档→原型→试玩→反馈→平衡循环）、数据驱动技能配置实践。
> 本文先摆业界常态，再对到 warden 现状（能力卡/BAL 锚点/靶场影棚都是现成的），最后给二期的讨论问题。

## 1. 业界标准工作流（调研归纳）

```
立意 ──► 规格文档 ──► 灰盒原型 ──► 验证闭环 ──► 表现层 ──► 平衡迭代（循环）
（fantasy）  （one-pager）  （数据驱动）  （读数+实测）  （特效音效）  （只调数据不动逻辑）
```

| 步 | 干什么 | 关键产物 |
|---|---|---|
| ① 立意 | 这个技能回答什么体验问题（"玩家此刻需要什么主动手段"）；反制/交互边界 | 一句话 kit 定位 |
| ② 规格文档 | 技能 one-pager：机制、数值**初稿**、瞄准/施放交互、反馈清单、数值锚点行 | 设计层源文件条目 |
| ③ 灰盒原型 | **无美术**实现（占位特效/无特效），数值进数据表，快速试手感 | 可玩灰盒 + 数据表 |
| ④ 验证闭环 | 自动读数（DPS/占比）+ 训练场实测；不达标回 ②③ | 读数报告 |
| ⑤ 表现层 | 逻辑与数据冻结后接特效/音效/动画（分件规范） | 表现验收 |
| ⑥ 平衡迭代 | **只动数据**（表/曲线），逻辑零改动；锚点对照 + 回归钉死 | 版本化数值 |

（服务型游戏还有第⑦步遥测回流——warden 单机，跳过。）

## 2. 架构共性（以 UE GAS 为代表的行业教训）

即使不用 UE，各家能力系统的共识高度一致：

1. **技能 = 数据 + 行为**：行为是稳定骨架（激活/结束生命周期、瞄准方式）；数据（冷却/消耗/数值/
   持续）全部外置成资产——**冷却和消耗本质是"效果"，不是代码分支**（GAS 里冷却就是一种持续效果）。
2. **标签驱动交互**：技能互斥/打断/加成用标签声明（激活时携带什么、被什么阻挡、打断什么），
   不写硬编码 if——技能数量增长后这是唯一的可维护路径。
3. **逻辑稳定、数据频调**：平衡迭代期每天改几十次数值、零次改逻辑——所以数据必须是单源表，
   改一处全局生效、可 diff、可回滚。
4. 规格先行：动手前 one-pager 必须能回答"锚点行"（这个技能的成功指标是什么）。

## 3. 对到 warden：现状盘点

**已经有的（比想象中齐）**：

- SK1 框架：冷却（真时间连续）、点地/瞬发瞄准、热键与按钮、未实装门控——对应业界"行为骨架"；
- requirements §17 = 规格文档层（设计唯一依据）；§16.9 操作归属法则 = 交互边界检查表；
- BAL2 锚点行"技能伤害贡献 ≤ 全场输出 20%"——对应"锚点行"实践；
- **靶场 + 影棚（刚建成）= 第④⑤步的验收工具**：靶场可加"技能实放"面板（CD 置零连放看特效与结算），
  影棚可预览技能特效资产——这是本次工作流升级的最大红利。

**缺口（本讨论要补的）**：

| 缺口 | 影响 | 建议 |
|---|---|---|
| 技能数值散落（`SKILL_COOLDOWNS` 在 resources，流星/新星/狂暴常量在 skills.rs） | 平衡期改数值要翻两个文件，无单源 | 收拢成 `SkillBalance` 表（ADR-0008 不变，仍留代码，只是单源） |
| 无技能 one-pager 模板 | 立意/反制/锚点靠记忆 | 在 requirements §17 下加条目模板 |
| 技能特效无验收通道 | 表现层只能实机试 | 复用 N4 结论：素材岩库 / 绑定游戏 fx / 预览走靶场（技能面板） |
| 二期方向未拍板 | GDD 点子池躺着 | 见 §5 讨论问题 |

## 4. 提议：warden 技能工作流六步（映射能力卡）

```
① 立意卡（一句话体验 + §16.9 归属检查：这技能归指挥官还是塔？热键容量？）
② 规格卡（one-pager 模板进 requirements §17.x：机制/数值初稿/交互/反馈/锚点行）
③ 灰盒卡（行为骨架实现 + 数值进 SkillBalance 单源表；占位特效或无特效）
④ 验收卡（BAL 读数扩展"技能贡献占比"行；靶场技能面板实放实测；锚点不达标回②）
⑤ 表现卡（特效素材岩库 → 绑定进 fx → 靶场动态验收 + 影棚预览）
⑥ 平衡迭代（只改 SkillBalance + 锚点对照；每期全量回归钉死）
```

一技能一组卡、每卡一提交；①②设计负责人拍板，③-⑥ AI 主刀——与现行能力卡流程完全同构，
只是把"技能"的规格模板和验收工具补齐。

## 5. 待讨论（下次技能会话的议题）

1. **二期范围拍板**（GDD 点子池三选）：融合塔主动技能 / 技能随机获取（三选一池） / Meta 技能强化——
   先做哪个？我推荐融合塔主动（复用 SK1 框架最多，且给融合塔补"新机制"卖点）。
2. **数值单源**：`SkillBalance` 收拢是否随第一张二期卡一并做？
3. **靶场技能面板**：给靶场加"技能 CD 置零连放"（原 SM3 设想的回归）——随二期首卡带上？
4. 模板细化：one-pager 字段有没有要加的（冷却定位？升级路线？）。

## 6. 调研参考

- UE GAS 官方文档与社区深读（x157）：能力生命周期、标签交互、冷却=持续效果、DataTable 数据驱动
- 通用流程：设计文档 → 原型 → 试玩 → 反馈 → 平衡迭代（多来源一致）
- 数据驱动实践：规则随平衡频变而逻辑保持稳定——与 ADR-0008"数据与逻辑分离≠外部化"互证
