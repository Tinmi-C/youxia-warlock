# 技能设计工作流 v2 · 独立开发 + AI 快速验证版（讨论稿）

> v1 调研了业界六步流水线（立意→规格→灰盒→验证→表现→平衡）；v2 按负责人定位重写：
> **独立开发 + AI 协作，要快速验证、稳定高效**。业界流程为三角色（设计/实现/QA）的传递成本而生，
> 我们没有传递成本——人和 AI 的分工是：**人管两个判断，AI 管其余一切，且每轮自证**。

## 1. 设计原则：为什么能比业界快一个量级

| 业界的成本 | 我们的现实 |
|---|---|
| 设计文档→程序→QA 的**传递与等待** | 人一句话立意，AI 直接按卡实现（卡=规格，无需二次传递） |
| 试玩要排期组局 | **靶场实放 30 秒一轮**（CD 置零连放、慢放逐帧） |
| 数值改动走版本/评审 | **改表→跑读数**，分钟级（ADR-0008：数值留代码单源表） |
| 平衡回归靠人力 | **headless 断言 + BAL 读数自动钉死**，AI 改坏立刻红 |
| 表现验收靠实机试玩 | **靶场动态验收 + 影棚资产预览**（刚建成的工具链） |

**稳定性的来源**（流程里永不动的四根柱子）：SK1 行为骨架冻结（数据/生命周期不改）·
数值单源表（`SkillBalance`，所有技能数值一处）· 验收三件套（断言=行为 / BAL=数值 / 靶场=手感表现）·
每技能一组回归断言。

## 2. 三循环工作流

```
循环A 立意（人拍板，10-30 分钟一次）
  你一句话立意 ──► AI 三问 ──► 迷你规格入卡 ──► 你拍板
                  （归属§16.9？反制/边界？锚点行？）
                       │ 拍板后进入 B
循环B 数值（AI 主刀，每轮 5-15 分钟）
  AI 灰盒实现/改表 ──► 断言+读数自证 ──► 你靶场实测 30 秒
        ▲                                    │
        └──────── 手感不对，改表再来 ◄─────────┘
                       │ 满意后进入 C
循环C 表现（AI 主刀，30-60 分钟）
  特效素材（岩库）──► 绑定进 fx ──► 靶场动态验收 ──► 一卡一提交（断言钉死）
```

- **人只做两个判断**：立意好不好（循环 A）、手感对不对（循环 B 的 30 秒实测）。其余——实现、自证、
  读数、回归、特效接入、文档——全部 AI。
- **AI 每轮自证**是效率的核心：不等人工验证发现"改 A 坏 B"，断言和读数先红了。
- 循环 B 内**永不碰逻辑**，只改 `SkillBalance` 表——这是"稳定"的另一半来源。

## 3. 循环 A 的迷你规格模板（入 requirements §17.x，五行以内）

```yaml
技能: <名字>
立意: <一句话：它回答玩家此刻的什么问题>
归属: 指挥官/塔（§16.9 检查：热键容量？与现有技能互斥？）
数值锚点: <可测指标，如：贡献 ≤ 全场输出 20% / 减速覆盖 ≥ 5 只·2s>
边界: <反制/失败条件/与锁建造铁律的关系>
```

不再要求业界式完整 one-pager——锚点行和归属检查必须答，其余实现卡里自然展开。

## 4. 流程基建（建议随二期首卡一并落，各一卡）

1. **`SkillBalance` 单源表**：现有 `SKILL_COOLDOWNS` + 散在 skills.rs 的流星/新星/狂避常量收拢
   （仍留代码，ADR-0008 不变）——循环 B 的前提。
2. **靶场技能面板**：Range 面板加"技能 CD 置零 + 连放"，靶场秒变技能实测台——循环 B 的另一半前提。
3. **BAL 技能占比读数**：balance.rs 加"技能贡献占比"行（BAL2 锚点行已立，只差读数通道）。

这三张基建卡做完，三循环就全速运转；此后每个新技能 = A 一次 + B 若干轮 + C 一次。
