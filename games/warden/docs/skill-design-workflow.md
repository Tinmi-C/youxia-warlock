# 技能设计工作流 v2 · 独立开发 + AI 快速验证版（讨论稿）

> v1 调研了业界六步流水线（立意→规格→灰盒→验证→表现→平衡）；v2 按负责人定位重写：
> **独立开发 + AI 协作，要快速验证、稳定高效**。业界流程为三角色（设计/实现/QA）的传递成本而生，
> 我们没有传递成本——人和 AI 的分工是：**人管两个判断，AI 管其余一切，且每轮自证**。

## 1. 设计原则：为什么能比业界快一个量级

| 业界的成本 | 我们的现实 |
|---|---|
| 设计文档→程序→QA 的**传递与等待** | 人一句话立意，AI 直接按卡实现（卡=规格，无需二次传递） |
| 试玩要排期组局 | **靶场实放 30 秒一轮**（CD 置零连放、慢放逐帧） |
| 数值改动走版本/评审 | **改表→跑读数**，分钟级（ADR-0008：数值留代码单源表） |
| 平衡回归靠人力 | **headless 断言 + BAL 读数自动钉死**，AI 改坏立刻红 |
| 表现验收靠实机试玩 | **靶场动态验收 + 影棚资产预览**（刚建成的工具链） |

**稳定性的来源**（流程里永不动的四根柱子）：SK1 行为骨架冻结（数据/生命周期不改）·
数值单源表（`SkillBalance`，所有技能数值一处）· 验收三件套（断言=行为 / BAL=数值 / 靶场=手感表现）·
每技能一组回归断言。

## 2. 三循环工作流

```
循环A 立意（人拍板，10-30 分钟一次）
  你一句话立意 ──► AI 三问 ──► 迷你规格入卡 ──► 你拍板
                  （归属§16.9？反制/边界？锚点行？）
                       │ 拍板后进入 B
循环B 数值（AI 主刀，每轮 5-15 分钟）
  AI 灰盒实现/改表 ──► 断言+读数自证 ──► 你靶场实测 30 秒
        ▲                                    │
        └──────── 手感不对，改表再来 ◄─────────┘
                       │ 机制达标后进入 C
循环C 表现/手感（AI 主刀 + 人多轮实测，每轮 5-15 分钟）
  AI 出特效/调参 ──► 靶场慢放逐帧实测 ──► 人判手感 ──► 调参再来
        ▲                                    │
        └── 节奏/强度/可读性不对，改 FxStyle 表 ◄─┘
                       │ 满意后钉死提交
```

- **人做两个判断，但第二个出现两次**：立意好不好（循环 A 一次）、手感对不对（循环 B 的机制手感 +
  循环 C 的表现手感——两层手感，后者轮数通常更多）。
- **AI 每轮自证**是效率的核心：不等人工验证发现"改 A 坏 B"，断言和读数先红了。
- 循环 B 内**永不碰逻辑**，只改 `SkillBalance` 表；循环 C 内同样**只改 `FxStyle` 表**——这是"稳定"的另一半。

## 2.5 表现循环细则（v3 新增——特效是手感本身，不是贴皮）

负责人反馈定调：**特效直接影响游戏体验**。三个推论已进流程：

1. **占位反馈进循环 B**：灰盒阶段就必须有可读反馈（现有 FX 爆圈/闪白就是这个角色）——
   流星三发的间隔既是数值也是观感，机制手感离不占位特效；
2. **循环 C 是独立迭代循环**（同 B 的结构，不是一次性步骤）：AI 出特效变体/调参 →
   靶场**慢放（0.25x）+ 逐帧**实测 → 人按下面的清单判 → 改表再来。每轮 5-15 分钟；
3. **表现参数全部数据化**（`FxStyle` 表，与 `SkillBalance` 同哲学）：时长/强度/尺寸/颜色/节奏/
   衰减曲线都是表字段——**手感调优也是改表，不是改代码**（ART7/8 的后坐参数进 TowerDef
   已验证同款做法）。声音同循环：素材岩库 → 绑定游戏 → 靶场验。

**人的手感判断清单**（循环 C 每轮照着过，30 秒-2 分钟）：

- [ ] 前摇可读（按下去到生效，看得见要发生什么）
- [ ] 命中帧明确（打击的那一帧"疼"不"疼"）
- [ ] 范围可读（AOE 边界一眼看清，不用猜）
- [ ] 消散干净（不留残渣、不拖泥带水）
- [ ] 连放不腻（CD 置零连按十次，视觉不糊成一团）
- [ ] 与场景分层（特效不被地形/单位吃掉，对比度够）

## 3. 循环 A 的迷你规格模板（入 requirements §17.x，五行以内）

```yaml
技能: <名字>
立意: <一句话：它回答玩家此刻的什么问题>
归属: 指挥官/塔（§16.9 检查：热键容量？与现有技能互斥？）
数值锚点: <可测指标，如：贡献 ≤ 全场输出 20% / 减速覆盖 ≥ 5 只·2s>
反馈清单: <前摇/命中/范围/消散的表现意图，一两句——循环 C 的验收依据>
边界: <反制/失败条件/与锁建造铁律的关系>
```

不再要求业界式完整 one-pager——锚点行和归属检查必须答，其余实现卡里自然展开。

## 4. 流程基建（建议随二期首卡一并落，各一卡）

1. **`SkillBalance` 单源表**：现有 `SKILL_COOLDOWNS` + 散在 skills.rs 的流星/新星/狂避常量收拢
   （仍留代码，ADR-0008 不变）——循环 B 的前提。
2. **`FxStyle` 表**：现有 FX 常量（爆圈半径/时长、闪白时长等）收拢为表现参数表——循环 C 的前提
   （表驱动手感调优）。
3. **靶场技能面板**：Range 面板加"技能 CD 置零 + 连放"，靶场秒变技能实测台——循环 B/C 共用的实测仪器。
4. **BAL 技能占比读数**：balance.rs 加"技能贡献占比"行（BAL2 锚点行已立，只差读数通道）。

这三张基建卡做完，三循环就全速运转；此后每个新技能 = A 一次 + B 若干轮 + C 一次。
